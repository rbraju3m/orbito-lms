# I18N.md — Multilingual interface and RTL (O5, O8)

The product ships in English and Bengali (`ORBITO_SUPPORTED_LOCALES=en,bn`,
`MASTER_PLAN.md` decision 4), and until this work only the data model knew
it: `users.locale` and `courses.locale` existed, the font stack carried Noto
Sans Bengali, and every word on every screen was English typed into a
component.

Written as a plan before the code; each slice records what it shipped, and
where that differs from the plan, in its own section. **I1 is built.**

Code: `app/Domain/Platform/Enums/Locale.php`, `Support/LocaleResolver.php`,
`Http/Middleware/SetLocale.php`; `web/src/shared/i18n/`, `web/src/app/LocaleSync.tsx`,
`web/src/shared/lib/{datetime,money,number,bytes}.ts`.

---

## 1. What this is, and what it is not

| | |
|---|---|
| **Is** | The INTERFACE in the reader's language: labels, messages, emails, formatted dates, numbers and money |
| **Is** | The plumbing for right-to-left scripts, so adding one later is a locale, not a rewrite |
| **Is not** | One course in two languages. That is content translation — ADR-10's `translations` table — and stays in P18 (§6) |
| **Is not** | Machine translation of anything an author typed. A course is in the language its author wrote it in, and `courses.locale` says which |

**Bengali is a left-to-right script.** RTL buys the first academy nothing; it
matters for Arabic, Urdu, Persian and Hebrew. So multilingual comes first and
RTL is foundation work, verified by mirroring a live page rather than
shipped as a language nobody asked for.

---

## 2. Decisions

| Question | Answer | Why |
|---|---|---|
| Which locale wins? | `?locale=` → the user's `locale` → the academy's default, **if it chose one** → `Accept-Language` → the academy's default → `en`; the first the academy offers | The person's own choice beats the academy's, which beats a browser guess — but a default nobody picked does not outrank the browser. Resolved ONCE, server-side, and echoed on `/auth/me` so the SPA never decides for itself |
| What is "not chosen"? | `users.locale` NULL | It defaulted to `'en'`, so every account looked like a person who had picked English and an academy's Bengali default would have reached nobody. No screen had ever offered a choice — the profile form posted a free-text box prefilled `en` — so the migration cleared them all |
| Library | A small `t()` of our own over `Intl.PluralRules` | First paint is 251.06 KB against a 255 KB budget. i18next + react-i18next alone would spend most of the headroom |
| Where English lives | In the source, as the key's default | English readers download no catalogue at all |
| Where Bengali lives | One JSON file per area (`catalogues/bn/learner.json` holds `learner.*`), each its own lazy chunk, all fetched together when a reader switches | English readers fetch none. A page that changed language paragraph by paragraph as chunks arrived would be worse than one short wait; splitting by area is one function if the catalogues grow |
| Digits in Bengali | Bengali digits (১২৩) — `Intl`'s default for `bn` | Natural for the reader. Prices, dates and counts all follow it; nothing parses a formatted number back |
| Who translates | Drafted with the slice, reviewed by a native speaker in the browser pass before it ships | A wrong word in front of a learner is a bug like any other |
| Server errors | Translated on the client from `error.code`; `message` stays the English fallback | Every error already carries a code. Two translations of one error — server and client — is two to keep in step |
| Notifications and mail | Rendered in the RECIPIENT's locale when the payload is frozen | §16: a notification is a frozen message. Freezing it in the actor's language would mail a Bengali reader in English because an English-speaking admin clicked |

## 3. Slices

Each slice is one commit to main after the full suite (`docs/ROADMAP.md`).

### I1 · Foundation — BUILT

**Backend**
- `Locale` enum — code, native name, direction; the only place a direction
  is declared. `orbito.locales.supported` says which cases an installation
  offers; a code there with no case is ignored.
- `LocaleResolver` is the only answer (§2). `SetLocale` applies it, in the
  `api` group and placed by the PRIORITY LIST after every tenancy
  middleware — a group middleware otherwise runs before a route's `tenant`,
  and the academy's default would silently never apply.
  `LocaleTenancyTest` ends tenancy to prove it; the harness hides the order.
- `/auth/me` and `GET /public/{academy}` carry `locale` — the answer and the
  `available` list. `/auth/me` resolves it in the resource, not from the app
  locale: login builds that payload before any academy was open.
- Academy settings `default_locale` and `enabled_locales`, in the `data`
  blob. The default must be enabled, judged on the MERGED result.
  `PATCH /account/profile {locale}` accepts only an enabled code, or null.
- `users.locale` is nullable (§2).

**Frontend**
- `shared/i18n`: `t(key, english, params)`, `plural()` over
  `Intl.PluralRules`, a zustand store holding the SERVER's answer, and
  `applyLocale()`, which switches only once the catalogue has landed — and
  lets the later of two switches win (the first version let a slow switch
  land after a newer one; a test caught it).
- `LocaleSync` applies the session's answer, sets `<html lang dir>`, wraps
  the tree in Mantine's `DirectionProvider`, and re-keys it on a switch —
  `t()` and the formatters are plain functions read during render. The public
  site applies its academy's answer when nobody is signed in.
- Every date, number, byte count and price goes through
  `shared/lib/{datetime,number,bytes,money}` with the resolved locale. Twenty
  bare `toLocaleString()` calls — which follow the BROWSER — are gone.
  `formatDay()` formats a `YYYY-MM-DD` the server names in UTC, because read
  as local time it is the day before for everybody west of Greenwich.
- The language picker is on the **profile page**, not the account menu: the
  menu is on first paint and the budget had 3.9 KB left. I1 cost 0.69 KB.
- **Languages** card on `/admin/academy`.

**RTL foundation**
- Six physical styles converted. `logicalStyles.test.ts` scans every source
  file and fails on `pl`/`pr`/`ml`/`mr`, `marginLeft`, `padding-right`,
  `left:`, `textAlign: 'right'` or `float`; an exception is named in it with
  its reason (the chart's SVG padding).
- **Planned a test-only pseudo-locale; did not need one.** Mantine's own
  styles key on `[dir]`, so the browser pass set `dir="rtl"` on a live page:
  the navbar moves to the right, the main area pads away from it, and labels,
  checkboxes and buttons mirror. Two things to look at when a real RTL
  language arrives: the item editor and live-session drawers open from the
  RIGHT (`position="right"`), and the chart's time axis stays left to right.

**Tests:** `LocaleTest` (the order, each fallback, the two writes, 403),
`LocaleTenancyTest` (the priority placement, the public site), and on the
client `i18n.test.ts`, `catalogues.test.ts` (a catalogue and the source must
agree), `logicalStyles.test.ts`, the profile picker and the Languages card.

**Browser pass** (headless Chrome, 360 and 1280, light and dark, axe): the
Languages card clean in all four; the academy default reaching an admin and a
student with no choice of their own, a student's English beating it, `null`
handing it back, and a stranger on the public site getting it. Bengali digits
on the plan meter and analytics. It found the account pages skipping from h1
to h3 (fixed on Profile and Security), raw `YYYY-MM-DD` days on analytics and
in its chart's spoken summary, and byte counts that never used the locale.

### I2 · Translate the interface, area by area

1. Learner shell — dashboard, catalogue, course page, player, quiz, cart, orders
2. Public site and auth pages
3. Studio, then admin and platform

Each area: strings into the catalogue, a `bn` catalogue, a browser pass in
Bengali at 360px and 1280px, light and dark. Bengali words run longer than
English ones; the narrow width is where that shows first.

Counts written into English sentences with a hand-made plural (one course,
three courses, decided by `n === 1`) become `plural()` calls as each area is
translated. About fifteen exist; I1 left them, because rewriting a sentence is
translation work.

### I3 · Text the server writes

- `lang/bn` for validation messages.
- Notifications and mail frozen in the recipient's locale.
- CSV headers.
- **Certificates.** dompdf does not shape complex scripts: Bengali conjuncts
  render as broken glyphs. This is its own spike — a different engine
  (headless Chrome) or a different pipeline — and its own decision.

## 4. What would reopen a decision

- **A second locale that is not left-to-right** — adds a `Locale` case, a font,
  mirrored directional icons, and a browser pass. If it needs more than that,
  I1 was built wrong.
- **An academy teaching the same course in two languages** — that is I4 (§6),
  not a change to anything here.
- **The catalogues outgrowing hand-editing** — a translation-management
  service reads and writes the same JSON files.

---

## 5. Traps

- `toLocaleString()` with no argument uses the BROWSER's locale. It is never
  correct here; use the shared formatters.
- A string built by concatenation cannot be translated — word order differs.
  Pass parameters to `t()`.
- Plurals are not `n === 1`. Use the plural helper.
